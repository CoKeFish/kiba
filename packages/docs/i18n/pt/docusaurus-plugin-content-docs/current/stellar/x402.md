# x402 padrão

[x402](https://www.x402.org) é o padrão aberto para cobrar por requisição HTTP: o servidor responde `402 Payment Required` com os requisitos de pagamento, o cliente assina o pagamento e repete a requisição. Na Stellar ele é implementado pelos pacotes oficiais `@x402/stellar`: o cliente assina apenas a **autorização** da transferência de USDC e um **facilitador** monta a transação, envia e paga a taxa de rede, então quem paga não precisa de XLM.

A Kiba fala x402 nas duas direções, com os pacotes oficiais.

## Pagar qualquer API x402 a partir do assistente

A ferramenta `call_url` do conector (e `POST /v1/x402/call` na API) permite que o assistente pague uma API que cobra com x402 na Stellar mesmo que ela não esteja no catálogo da Kiba.

```text
Usuário:    Chame https://api.exemplo.com/weather?city=Bogota e me diga o clima.
Assistente: call_url({ url: "https://api.exemplo.com/weather?city=Bogota" })
```

O que a Kiba faz:

1. Chama a URL sem pagamento. Se a API não responder 402, devolve a resposta como está, sem cobrar.
2. Lê os requisitos de pagamento do cabeçalho `PAYMENT-REQUIRED` e escolhe a opção na Stellar em USDC.
3. Desconta o preço do saldo do usuário (créditos, ou a carteira de pagamentos quando não há créditos).
4. Assina a autorização da transferência com a treasury da Kiba e repete a requisição com `PAYMENT-SIGNATURE`.
5. A API verifica e liquida on-chain pelo seu facilitador e responde com `PAYMENT-RESPONSE`, que traz o hash da transação.

A resposta ao assistente inclui o resultado da API, `cost`, `newBalance`, `payTo`, `txHash` e `explorerUrl` (stellar.expert). A chamada fica salva nos resultados da conta e a cobrança nas transações, com a assinatura da transação.

Regras:

- **Teto por chamada.** 1 USD por padrão. Se a API cobrar mais, a Kiba não paga e avisa o assistente para repetir com `maxUsd`. Há um teto absoluto de 20 USD.
- **Reembolso.** Se a API rejeitar a chamada paga sem liquidar o pagamento, a cobrança volta ao saldo. Se liquidou e mesmo assim respondeu erro, o pagamento já está na rede e a resposta avisa.
- **Só destinos públicos.** URLs `https` sem credenciais e fora de redes privadas.
- **Métodos** GET, POST, PUT, PATCH e DELETE, com corpo JSON e cabeçalhos próprios. Os cabeçalhos de pagamento são colocados pela Kiba.

Parâmetros de `call_url`: `url` (obrigatório), `method`, `body`, `headers`, `maxUsd`.

## Cobrar com x402 no seu serviço

Todo serviço publicado com o SDK pode aceitar, além da cotação da Kiba, pagamentos x402 padrão de **qualquer** cliente. Uma variável de ambiente ou um campo de configuração ativa:

```bash
npm i @x402/core @x402/stellar      # Node 22 ou superior
KIBA_X402_FACILITATOR=https://x402.org/facilitator   # ou `self`
```

```ts
new AgentProvider({
  service: 'meu-servico',
  pricePerCall: 0.01,
  x402: { facilitatorUrl: 'https://x402.org/facilitator' }, // ou { selfFacilitate: true }
});
```

Com x402 ativado:

- O 402 leva o cabeçalho `PAYMENT-REQUIRED` com o preço **daquela** requisição (incluindo o preço dinâmico de `priceFn`), sua conta como `payTo` e USDC na sua rede. O corpo continua sendo a cotação da Kiba, então o conector funciona como antes.
- Uma requisição com `PAYMENT-SIGNATURE` é verificada antes de executar qualquer coisa: rede, ativo, conta e valor precisam ser os do seu serviço para aquela requisição. Se for válida, seu handler roda e depois o pagamento é liquidado on-chain. O 200 leva `PAYMENT-RESPONSE` com o hash e `_payment.standard = "x402"`.
- Se o pagamento não for válido ou não liquidar, a resposta é 402 com o motivo e uma nova cotação, e o resultado não é entregue.
- O manifest anuncia `x402: { network, payTo }` para que os clientes saibam que podem pagar assim.

Facilitadores:

| Opção | O que faz | Quando |
|---|---|---|
| `https://x402.org/facilitator` | Verifica, envia a transação e paga a taxa. Sem chave. | Testnet |
| OpenZeppelin Channels | O mesmo, com chave de API (`KIBA_X402_FACILITATOR_API_KEY`). | Testnet e mainnet |
| `self` | O seu próprio serviço verifica e envia a transação com a sua conta e paga a taxa (cerca de 0,00001 XLM) do seu XLM. Sem terceiros. | Testnet e mainnet |

Sua conta precisa de trustline de USDC para receber pagamentos; `bootstrap()` cria.

## Como se encaixa com o trilho da Kiba

| | Trilho da Kiba | Faixa x402 |
|---|---|---|
| Quem paga a quem | O assistente paga serviços do catálogo | O assistente paga qualquer API x402; qualquer cliente x402 paga seus serviços |
| Cobrança | Créditos ou carteira de pagamentos, assinada pela plataforma, em milissegundos | Uma transação USDC por requisição, liquidada por um facilitador |
| Liquidação ao serviço | Contrato de pagamentos da Kiba, em lotes, com divisão 95/5 | Direto na sua conta, 100% do preço |
| Licenças | O pagamento leva a impressão digital do documento de licença | Não se aplica |

O x402 é a faixa de interoperabilidade: abre o catálogo para fora e traz clientes de fora. O trilho da Kiba continua sendo o caminho rápido dentro do assistente.

## Exemplos

- [`examples/x402-seller`](https://github.com/CoKeFish/kiba/tree/main/examples/x402-seller): uma API de terceiros que cobra com x402 (`@x402/express`) e que a Kiba paga com `call_url`.
- [`examples/x402-buyer`](https://github.com/CoKeFish/kiba/tree/main/examples/x402-buyer): um cliente x402 genérico (`@x402/fetch`) pagando um serviço Kiba sem o conector.

```bash
curl -X POST https://api.kiba.tools/v1/x402/call \
  -H "Authorization: Bearer $KIBA_TOKEN" -H "Content-Type: application/json" \
  -d '{ "url": "https://api.exemplo.com/weather?city=Bogota", "maxUsd": 0.05 }'
```

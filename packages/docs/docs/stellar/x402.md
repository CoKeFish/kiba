# x402 estándar

[x402](https://www.x402.org) es el estándar abierto para cobrar por petición HTTP: el servidor responde `402 Payment Required` con los requisitos de pago, el cliente firma el pago y repite la petición. En Stellar lo implementan los paquetes oficiales `@x402/stellar`: el cliente firma solo la **autorización** de la transferencia USDC y un **facilitador** arma la transacción, la envía y paga la comisión de red, así que quien paga no necesita XLM.

Kiba habla x402 en las dos direcciones, con los paquetes oficiales.

## Pagar cualquier API x402 desde el asistente

La herramienta `call_url` del conector (y `POST /v1/x402/call` en la API) le permite al asistente pagar una API que cobre con x402 en Stellar aunque no esté en el catálogo de Kiba.

```text
Usuario:   Llama a https://api.ejemplo.com/weather?city=Bogota y dime el clima.
Asistente: call_url({ url: "https://api.ejemplo.com/weather?city=Bogota" })
```

Qué hace Kiba:

1. Llama a la URL sin pago. Si la API no responde 402, devuelve la respuesta tal cual, sin cobrar.
2. Lee los requisitos de pago de la cabecera `PAYMENT-REQUIRED` y elige la opción en Stellar con USDC.
3. Descuenta el precio del saldo del usuario (crédito, o la wallet de pagos si no hay crédito).
4. Firma la autorización de la transferencia con la treasury de Kiba y repite la petición con `PAYMENT-SIGNATURE`.
5. La API verifica y liquida on-chain a través de su facilitador y responde con `PAYMENT-RESPONSE`, que trae el hash de la transacción.

La respuesta al asistente incluye el resultado de la API, `cost`, `newBalance`, `payTo`, `txHash` y `explorerUrl` (stellar.expert). La llamada queda guardada en los resultados de la cuenta y el cargo en las transacciones, con la firma de la transacción.

Reglas:

- **Tope por llamada.** Por defecto 1 USD. Si la API cobra más, Kiba no paga y le dice al asistente que repita con `maxUsd`. Hay un tope absoluto de 20 USD.
- **Reembolso.** Si la API rechaza la llamada pagada sin liquidar el pago, el cargo vuelve al saldo. Si liquidó y aun así respondió error, el pago ya está en cadena y la respuesta lo avisa.
- **Solo destinos públicos.** URLs `https` sin credenciales y fuera de redes privadas.
- **Métodos** GET, POST, PUT, PATCH y DELETE, con cuerpo JSON y cabeceras propias. Las cabeceras de pago las pone Kiba.

Parámetros de `call_url`: `url` (obligatorio), `method`, `body`, `headers`, `maxUsd`.

## Cobrar con x402 en tu servicio

Todo servicio publicado con el SDK puede aceptar, además de la cotización de Kiba, pagos x402 estándar de **cualquier** cliente. Se activa con una variable de entorno o en la configuración:

```bash
npm i @x402/core @x402/stellar      # Node 22 o superior
KIBA_X402_FACILITATOR=https://x402.org/facilitator   # o `self`
```

```ts
new AgentProvider({
  service: 'mi-servicio',
  pricePerCall: 0.01,
  x402: { facilitatorUrl: 'https://x402.org/facilitator' }, // o { selfFacilitate: true }
});
```

Con x402 activado:

- El 402 lleva la cabecera `PAYMENT-REQUIRED` con el precio de **esa** petición (el precio dinámico de `priceFn` incluido), tu cuenta como `payTo` y USDC en tu red. El cuerpo sigue siendo la cotización de Kiba, así que el conector funciona igual.
- Una petición con `PAYMENT-SIGNATURE` se verifica antes de ejecutar nada: red, activo, cuenta y monto tienen que ser los de tu servicio para esa petición. Si vale, corre tu handler y después se liquida on-chain. La respuesta 200 lleva `PAYMENT-RESPONSE` con el hash y `_payment.standard = "x402"`.
- Si el pago no vale o no se liquida, la respuesta es 402 con el motivo y una nueva cotización, y el resultado no se entrega.
- El manifest anuncia `x402: { network, payTo }` para que los clientes sepan que pueden pagarte así.

Facilitadores:

| Opción | Qué hace | Cuándo |
|---|---|---|
| `https://x402.org/facilitator` | Verifica, envía la transacción y paga la comisión. Sin clave. | Testnet |
| OpenZeppelin Channels | Igual, con clave de API (`KIBA_X402_FACILITATOR_API_KEY`). | Testnet y mainnet |
| `self` | Tu propio servicio verifica y envía la transacción con su cuenta y paga la comisión (unos 0,00001 XLM) de su XLM. Sin terceros. | Testnet y mainnet |

Tu cuenta necesita trustline de USDC para recibir los pagos; `bootstrap()` la crea.

## Cómo encaja con el riel de Kiba

| | Riel de Kiba | Carril x402 |
|---|---|---|
| Quién paga a quién | El asistente paga servicios del catálogo | El asistente paga cualquier API x402; cualquier cliente x402 paga tus servicios |
| Cobro | Crédito o wallet de pagos, firmado por la plataforma, en milisegundos | Una transacción USDC por petición, liquidada por un facilitador |
| Liquidación al servicio | Contrato de pagos de Kiba, por lotes, con reparto 95/5 | Directa a tu cuenta, el 100 % de la tarifa |
| Licencias | El pago lleva la huella del documento de licencia | No aplica |

x402 es el carril de interoperabilidad: abre el catálogo hacia fuera y trae clientes de fuera. El riel de Kiba sigue siendo el camino rápido dentro del asistente.

## Ejemplos

- [`examples/x402-seller`](https://github.com/CoKeFish/kiba/tree/main/examples/x402-seller): una API ajena que cobra con x402 (`@x402/express`) y a la que Kiba le paga con `call_url`.
- [`examples/x402-buyer`](https://github.com/CoKeFish/kiba/tree/main/examples/x402-buyer): un cliente x402 genérico (`@x402/fetch`) que le paga a un servicio Kiba sin el conector.

```bash
curl -X POST https://api.kiba.tools/v1/x402/call \
  -H "Authorization: Bearer $KIBA_TOKEN" -H "Content-Type: application/json" \
  -d '{ "url": "https://api.ejemplo.com/weather?city=Bogota", "maxUsd": 0.05 }'
```
